# ZK Passport smart contracts reference

:::info
We're in process of migrating from legacy Circom circuits to Noir Ultra Plonk for passport verification during registration. Until the migration is complete, both are supported resulting in existence of `...Noir` methods
:::

A set of contracts facilitating self-issued anonymous identities based on the ZK Passport tech.

Currently, there are seven contract sections:
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/state">State </OutLink>
 — main `StateKeeper` contract and a set of utility contracts. `StateKeeper` acts as a singleton state instance with which registration contracts interact. `StateKeeper` does the following:
    * Stores the Sparse Merkle Tree with registered identities;
    * Stores the Sparse Merkle Tree with registered certificates of ICAO members;
    * Stores and manages some passport and identity information;
    * Manages the "Passport \<> Identity" bonds.
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/registration">Registration</OutLink>
 — primary section with `Registration2` contract, that:
    * Allow users registration (with binding of their identity to the passport);
    * Allow revocation of passport-identity binding;
    * Allow re-issuance of previously revoked identity;
    * Allow registration and revocation of ICAO member's certificates (calls `StateKeeper`);
    * Call one of the verifier contracts, based on the provided passport type, to verify ZKP;
    * Manage different dispatchers.

    On Gnosis, the section also includes `NoAARecovery`, which restores the identity of documents without Active Authentication.
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/passport/verifiers2">Verifiers</OutLink>
 — auto-generated contracts, the main purpose of which is to verify the ZKP.
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/passport/dispatchers">Dispatchers</OutLink>
 — acts as a bridge between registration contracts and:
    * authenticators corresponding to different passport types, if it is a passport dispatcher;
    * signers, if it is a certificate dispatcher.
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/certificate/signers">Signers</OutLink>
 — responsible for verifying the signature of the ICAO member's certificate. It also stores information required for signature verification (e.g. RSA exponent).
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/passport/authenticators">Authenticators</OutLink>
 — perform the passport Active Authentication (AA).
1. <OutLink href="https://github.com/rarimo/passport-contracts/tree/master/contracts/utils">Utilities</OutLink>
 — some utility contracts, such as X509, SHA1, RSA implementations in solidity language and other.

- `passportVerifiers` — mapping from passport type to its verifier contract;

- `revokeCertificate(...)` — revokes an expired ICAO member's X509 certificate (calls `StateKeeper` contract);

- `revoke(...)` — revokes the identity and its passport by the user's will, marks the passport (and identity) as revoked;
- `reissueIdentity(...)` — re-issues previous passport \<> identity bond by migration to a new identity;
- `reissueIdentityViaNoir(...)` — the same as `reissueIdentity(...)` but uses Noir proof instead of Circom;
- `updateDependency(...)` — adds or removes, depending on the method provided, a dispatcher via Rarimo TSS;

## `NoAARecovery`

:::info
`NoAARecovery` is deployed on Gnosis only. See [ZK Passport on Gnosis Chain](/zk-passport/gnosis-deployment).
:::

Restores the identity of a document without Active Authentication (`P_NO_AA`). Such a document can't prove possession of its chip key, so `Registration2` can't revoke its bond: without this module, a lost identity key would lock the document forever. `NoAARecovery` lets the holder of the document move the bond to a new identity key:

1. `requestRecovery(...)` — the holder proves the document again with a Noir register proof for the new identity key;
2. `recoveryDelay` (3 days) passes, during which the current key holder can cancel the request;
3. `finalizeRecovery(...)` — anyone moves the bond: the old identity is revoked and the new one is issued with an incremented `identityReissueCounter`.

The module is registered in `StateKeeper` as `NO_AA_RECOVERY`, which allows it to call `revokeBond(...)` and `reissueBondIdentity(...)`.

### Interface

```solidity
contract NoAARecovery is Initializable, UUPSUpgradeable {

    enum Action {
        None,
        CancelRecovery,
        LockRecovery,
        UnlockRecovery
    }

    struct RecoveryRequest {
        bytes32 oldIdentityKey;
        bytes32 newIdentityKey;
        uint256 dgCommit;
        uint64 readyAt;
    }

    StateKeeper public stateKeeper;
    Registration2 public registration;

    address public keyPossessionVerifier;

    uint64 public recoveryDelay;
    uint64 public lockDuration;

    mapping(bytes32 => bool) public allowedZkTypes;
    mapping(bytes32 => uint64) public lockedUntil;
    mapping(bytes32 => bool) public isRecoveryLocked;
    mapping(bytes32 => uint256) public nonces;

    function requestRecovery(
        bytes32 certificatesRoot_,
        uint256 identityKey_,
        uint256 dgCommit_,
        bytes32 passportHash_,
        bytes32 zkType_,
        bytes memory zkPoints_
    ) external virtual {
        /* ... */
    }

    function finalizeRecovery(bytes32 passportHash_) external virtual {
        /* ... */
    }

    function cancelRecovery(bytes32 passportHash_, bytes memory zkPoints_) external virtual {
        /* ... */
    }

    function lockRecovery(bytes32 passportHash_, bytes memory zkPoints_) external virtual {
        /* ... */
    }

    function unlockRecovery(bytes32 passportHash_, bytes memory zkPoints_) external virtual {
        /* ... */
    }

    function getRecoveryRequest(bytes32 passportHash_) external view returns (RecoveryRequest memory);

    function getKeyPossessionMessage(bytes32 passportHash_, Action action_) public view returns (bytes32);

}
```

- `recoveryDelay` — time between a recovery request and its finalization;
- `lockDuration` — how long the document is locked after a cancelled or contested request;
- `allowedZkTypes` — register circuit types accepted for recovery (the Noir `..._NA` types);
- `lockedUntil` — the time until which no recovery can be requested for the document;
- `isRecoveryLocked` — whether the current key holder has disabled recovery of the document;
- `nonces` — the number of KeyPossession proofs used for the document, part of the proof message;
- `requestRecovery(...)` — requests to move the bond of `passportHash_` to `identityKey_`. Verifies the register proof with the `Registration2` verifier of `zkType_` against a valid certificates root. If a request for another key is already pending, the request is contested: both are dropped and the document is locked for `lockDuration`;
- `finalizeRecovery(...)` — moves the bond once `readyAt` has passed, if the active identity has not changed since the request. Callable by anyone;
- `cancelRecovery(...)` — drops the pending request and locks the document for `lockDuration`. Requires a KeyPossession proof of the active identity key;
- `lockRecovery(...)` — disables recovery of the document and drops the pending request, if any. Requires a KeyPossession proof. If the identity key is lost while locked, the document can never be recovered;
- `unlockRecovery(...)` — enables recovery again. Requires a KeyPossession proof;
- `getRecoveryRequest(...)` — returns the pending request of the document;
- `getKeyPossessionMessage(...)` — returns the message the next KeyPossession proof for the document and action must be bound to;

The register proof of `requestRecovery(...)` has the same public signals as in `registerViaNoir(...)`: AA public key hash (always zero), passport hash, DG1 commitment, identity key and certificates root.

A KeyPossession proof is a Noir proof of the identity secret key, generated with the <OutLink href="https://github.com/deantech-io/passport-zk-circuits-noir/tree/feature/key-possession/key_possession">`key_possession`</OutLink> circuit. Its public signals are the active identity key and the message `keccak256(abi.encode(chainId, address(this), action, passportHash, nonce)) >> 8`, so each proof is valid for one document, one action and one use.

Reissued bonds have `identityReissueCounter` of 1 or more. Votings that set `identityCounterUpperBound` to 0 exclude identities recovered after the proposal start.

For the full implementation, see <OutLink href="https://github.com/deantech-io/passport-contracts/blob/feature/no-aa-recovery/contracts/registration/NoAARecovery.sol">NoAARecovery.sol</OutLink> at the GitHub.

## `RegistrationSMTReplicator`

### Interface

```solidity
contract RegistrationSMTReplicator is IPoseidonSMT {
    uint256 public constant ROOT_VALIDITY = 1 hours;
    string public constant REGISTRATION_ROOT_PREFIX = "Rarimo root";

    address public sourceSMT;
    bytes32 public latestRoot;
    uint256 public latestTimestamp;

    event RootTransitioned(bytes32 newRoot, uint256 transitionTimestamp);

    function __RegistrationSMTReplicator_init(
        address[] memory oracles_,
        address sourceSMT_
    ) external;

    function addOracles(address[] memory oracles_) external;
    function removeOracles(address[] memory oracles_) external;
    function setSourceSMT(address newSourceSMT_) external;

    function transitionRoot(bytes32 newRoot_, uint256 transitionTimestamp_) external;
    function transitionRootWithSignature(
        bytes32 newRoot_,
        uint256 transitionTimestamp_,
        bytes memory signature_
    ) external;

    function isRootValid(bytes32 root_) external view returns (bool);
    function isRootLatest(bytes32 root_) public view returns (bool);
    function isOracle(address oracle_) public view returns (bool);
    function getOracles() external view returns (address[] memory);
}
```

- Deployed on target chains to replicate the Registration SMT root when the canonical `StateKeeper` is not directly available.
- Root updates can be pushed by:
  - Authorized oracles via `transitionRoot(...)`.
  - Anyone with an oracle-signed message via `transitionRootWithSignature(...)` using `keccak256(abi.encodePacked(REGISTRATION_ROOT_PREFIX, sourceSMT, address(this), newRoot, timestamp))` recovered with ECDSA.
- `isRootValid(root)` returns true if the root is the latest or if it was observed within `ROOT_VALIDITY` (1 hour), enabling lightweight freshness checks by verifiers depending on `IPoseidonSMT`.
- Owners manage the oracle set and can update `sourceSMT`; contract follows UUPS upgradeability and multi-owner controls.
